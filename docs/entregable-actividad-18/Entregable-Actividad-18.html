Objetivo: reconocer barreras de uso permanentes, temporales y situacionales, resolverlas mediante ajustes compartidos y reducir el ruido visual sin eliminar funciones financieras.

1. Tabla de análisis de inclusión

Se aplica el enfoque Microsoft Inclusive Design a dos tareas críticas de Fluye. Una limitación permanente puede compartir barreras con una lesión temporal o con las condiciones del entorno; el ajuste se diseña para beneficiar simultáneamente a estos usuarios.

EscenarioPermanenteTemporalSituacionalAjuste concreto compartido
Registrar un ingreso o gastoBaja visión o daltonismo: dificultad para identificar campos, tipo de movimiento y selección de cuenta.Lesión de mano o brazo: uso del teclado o interacción con una sola mano.Registro desde el celular bajo sol intenso o con una mano ocupada.Modo Alto contraste: texto negro sobre blanco, acción principal inversa, peso 700 y bordes sólidos de 2 px. Foco visible, controles de al menos 44 px y selección subrayada. Se conservan etiquetas y errores escritos.
Consultar saldo, buscar y corregir movimientosBaja visión o sordera: dificultad para leer datos de bajo contraste o percibir confirmaciones sonoras.Fatiga visual o lesión de brazo: necesidad de lectura clara y recorrido por teclado.Reflejos en la pantalla y ruido en transporte: no se distinguen bien los datos ni se oyen confirmaciones.Alto contraste en resumen, historial, filtros y diálogos; enlace Saltar al contenido y retorno del foco al cerrar. Se mantienen signos +/−, etiquetas de ingreso/gasto y avisos escritos mediante status/alert, sin depender solo de color o audio.

Beneficio transversal: la preferencia se conserva en el navegador y está disponible sin iniciar sesión. Es independiente del tema claro/oscuro. Los controles nuevos se integran en los diccionarios español y quechua.

2.2. Preferencia persistente y retorno de foco

Archivo: src/scripts/inclusive.js

Alterna el contraste, conserva la preferencia cuando localStorage está disponible y sincroniza el estado accesible. Los diálogos nativos conservan Escape; al cerrarlos se devuelve el foco al activador.

// Reading preferences work independently of authentication and audio.
const root = document.documentElement;
const sync = () => {
  for (const button of document.querySelectorAll('[data-contrast-toggle]')) {
    button.setAttribute('aria-pressed', String(root.dataset.contrast === 'high'));
  }
};
document.addEventListener('click', (event) => {
  if (!event.target.closest?.('[data-contrast-toggle]')) return;
  root.dataset.contrast = root.dataset.contrast === 'high' ? 'normal' : 'high';
  try { localStorage.setItem('fluye_contrast', root.dataset.contrast); } catch {}
  sync();
});
window.addEventListener('storage', (event) => {
  if (event.key !== 'fluye_contrast') return;
  root.dataset.contrast = event.newValue === 'high' ? 'high' : 'normal';
  sync();
});
// Native dialogs handle focus trapping and Escape; keep the keyboard return point.
for (const dialog of document.querySelectorAll('dialog')) {
  let opener;
  // Capture the trigger before showModal moves focus into the dialog.
  document.addEventListener('click', (event) => {
    if (!dialog.open && event.target.closest?.('button, a')) opener = event.target.closest('button, a');
  }, true);
  dialog.addEventListener('close', () => { if (opener?.isConnected) opener.focus(); });
}
sync();
